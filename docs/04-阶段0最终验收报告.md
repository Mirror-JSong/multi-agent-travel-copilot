`BUDGET_INFEASIBLE` 的准确含义是：当前固定候选、必要约束和分阶段启发式搜索策略没有找到预算内方案。它不宣称数学意义上的所有候选组合均无解。

## 3. 预算专项 Fixture

专项 Fixture 位于 `python/tests/test_budget_optimization.py`，与产品演示 Mock Provider 分离：

- `FixedFlightProvider`：往返各包含初始高分候选和低价候选。
- `FixedHotelProvider`：包含高评分初始酒店和满足最低评分的经济酒店。
- `FixedActivityProvider`：每天三个时段均包含高评分活动和经济活动。
- `NoLowerActivityProvider`：验证某轮无法改善仍继续后续策略。
- S8 内联 Provider：提供价格最低但日期、路线、舱位、评分、时段或兴趣不合格的候选。
- Counting Provider：证明预算调整期间航班只查询往返各一次、酒店一次、活动一次。

所有候选均为符合 Pydantic Schema 的 Mock 对象，具有稳定 ID、`source=mock` 和固定 `source_version=budget-fixture-v1`。

## 5. 集成、故障、并发与金额

### Pipeline 与 API

- 合法 `UserPreferences` 能完整经过 Preference、Destination、并行业务 Agent 和预算循环。
- `/api/plan` 保留原摘要字段，增加 `status` 和 `message`。
- `/api/plan/full` 返回候选快照、初始选择、初始/最终费用和完整调整历史。
- 非法输入返回 422；未预期内部异常返回 500。
- `BUDGET_INFEASIBLE` 是 HTTP 200 的业务结果；`FAILED` 通过结构化 `errors` 传播。

### Agent 故障

隔离注入执行异常、超时、必要结果缺失和 API 故障传播共 4 项测试，全部通过：

- 缺失费用不会按 0 元计算。
- 失败状态不会被 BudgetAgent 或 BudgetLoop 覆盖。
- 不会生成虚假的完整预算明细。
- 错误包含 Agent、错误代码、异常类型、原因及 required 标识。

### 并发和隔离

- Provider 连续调用五次及并发调用结果一致。
- 修改一次返回对象不会污染 Provider 后续结果。
- 两个并发规划请求的候选快照、推荐对象和调整历史互相独立。
- 同输入连续五次和不同 `PYTHONHASHSEED` 的新 Python 进程结果一致。

### 金额

- 费用统一在计算边界按两位小数归一化。
- `0.1`、`0.2` 等易出现二进制浮点误差的组合实际对账为：航班 0.9、酒店 0.8、活动 3.6、总计 5.3。
- 当前保留 JSON number 和有限 float；整体迁移 Decimal 作为后续技术优化，不是阶段 0 阻塞项。

## 9. 已知风险

1. `ParallelExecutor` 初始阶段仍将同一可变 State 传给三个 Agent。当前三个 Agent 只写各自独立结果字段，现有测试未发现覆盖；多个 Agent 同时失败时，错误列表顺序理论上可能受调度影响。后续应改为只读 PlanningContext、独立 AgentOutput 和编排器确定性合并。
2. `CandidateSnapshot` 通过深拷贝和预算优化器只读约定实现隔离，嵌套 Pydantic 对象并非语言级深层不可变。
3. 金额仍为有限 float 加两位小数归一化，尚未采用 Decimal。
4. Mock 数据用于工程演示，不代表真实市场价格、库存或天气。
5. 健康接口 Agent 数量仍为当前阶段固定值 6；未来加入 WeatherAgent 时应改为从注册表生成。

上述风险已记录且不破坏阶段 0 的必要验收不变量。
